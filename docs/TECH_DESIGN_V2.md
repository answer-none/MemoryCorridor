## 1. 项目概述

### 1.1 一句话定位

> **把家的记忆挂回真实的房间里**——在真实物品上挂一粒萤火般的光点，走近它，先听见当年的声音，光点绽放成那一刻的回忆；太久不去看，记忆会慢慢褪色，直到你再次点亮它。

### 1.2 三句话讲清体验

1. **挂**：手机浏览器把照片/录音/日记传进头显，捏着光点挂到房间里对应的老物件上（奶奶的缝纫机、毕业证书、旧沙发）。
2. **走**：一条星尘路径引你依次回访，每个光点先传来若隐若现的空间音频，点开后现实淡出、回忆在原位绽放（回忆重演）。
3. **传**：走完生成一面"星河回顾墙"；整个房间打包成一个 zip 发给家人，隐私记忆永远留在本地。

### 1.3 为什么它能得分（评分对齐表）

| 评分项 | 分值 | 拿分策略 | 对应设计 |
|---|---|---|---|
| 创新 | 25 | 做出"第一次的体验"：**记忆会褪色**（遗忘作为机制）是本项目独有的情感创新；MR 光点锚定 + 回忆重演的组合在同类作品（MemoryVR、空间相册类）中未见 | §4 三个签名机制 |
| 功能设计 | 25 | 真实需求（家庭记忆保存/代际传承）+ 核心闭环成立：挂→走→传，5 分钟可在现场完整演示一遍；浏览器上传解决"VR 里没法导入素材"的真实痛点 | §3 P0 收敛、§5.2 ImportServer |
| 界面视觉 | 15 | 统一"暮色暖光 + 萤火光点 + 尘埃粒子"美学；星河回顾墙是标志性画面；风格化渲染不吃显存 | §6 视觉规范 |
| 交互体验 | 15 | "先闻其声再见面"的空间化引导；悬停即预览；全手柄射线（模拟器可调试、录屏稳定）；防眩晕细节清单 | §7 交互规范 |
| 完成度 | 10 | 15 分钟内容闭环 + 开源（README/数据格式文档/Demo 素材包命中"开源可二开加分"） | §11 交付清单 |
| 路演 | 10 | 现场共创：评委手机传照片 → 30 秒挂光点 → 戴头显走读 → 导出 zip"带回家" | §12 路演剧本 |

## 2. 评分驱动的功能重划（核心变更）

### 2.1 P0 收敛为 7 项（必须闭环）

| # | 功能 | 验收口径 |
|---|---|---|
| 1 | 光点锚定 + 射线交互（含悬停预览、按类型配色） | 射线悬停光点 → 浮出小预览卡；扳机点开 |
| 2 | 三类记忆：图片 / 录音 / 日记（组合=图+音+日记自然叠加，**不做视频**） | 面板内三类内容正确呈现与关闭 |

| 4 | 手动排序 + 走读路线（星尘路径指引 + 星河回顾终点） | 按编排顺序走完全程并生成回顾墙 |
| 5 | 浏览器上传（图片/录音文件 + 日记表单，局域网 HTTP） | 手机浏览器传 1 图 1 音 1 日记，30 秒内可用 |
| 6 | 公开/隐私标记 + zip 导出/导入（隐私过滤） | 导出包内无 private 条目；他人导入可走读 |
| 7 | **记忆褪色机制**（创新点，实现成本低，必须进 P0） | 未回访记忆光点变暗、音频加低通；回访后恢复 |
| 8 | **欢迎房间**：首次进入自带 3 条精修记忆（含画面+专属音效） | 零上传即可完整体验（借鉴 immerGallery 的开箱即惊艳） |

### 2.2 降级去向（V1 → V2）

| V1 中的项 | 去向 | 理由 |
|---|---|---|
| 全景场景替换 | **P2** | 演示与核心闭环用不到"换背景"；省出的工时给褪色机制与视觉打磨 |
| 光点图标显隐开关 | P1 | 设置项不是得分点，一行代码随时补 |
| 个人档案（昵称+头像） | 简化为**名字选择**（无头像上传） | 档案价值在"归属过滤"，头像上传链路性价比低 |
| 视频记忆、组合记忆编辑器 | P1（视频仅低码率短片段） | 4GB 级显存 + 模拟器解码风险，V1 已列为风险 |
| 家庭本地多档案、多维排序、房间级隐私 | P1 | 导出/导入已足够演示"家庭场景"（妈妈的包导入即家庭库） |
| 云端同步、实时共创、3DGS | P2 不变 | 工期与硬件双重不可行 |

> 原则：**P0 只保留"现场 5 分钟能演示完整闭环"所必需的功能**。P1 全部服务于锦上添花，P2 只写在申报文档"二期规划"里（体现产品思考，不承诺实现）。

## 3. 三个签名机制（创新分主战场）

### 3.1 记忆褪色（Fading）—— "遗忘"作为机制

- **规则**：每条碎片记 `lastVisitedAt`；超过阈值天数未回访 → 光点亮度按天数衰减（最低 25%）、关联音频挂 `AudioLowPassFilter`（截止频率随天数降低，声音"隔着一层时间"）+ 音量 duck；回访即满血。
- **视觉隐喻**：光点像萤火虫，越久没人看，飞得越远越暗（光点半径随衰减同步缩小 + 漂浮动画幅度降低）。
- **实现**：`FadeController` 单脚本读 `lastVisitedAt` 算 0–1 衰减系数，驱动材质 emissive/alpha + 滤波器截止频率；每帧成本可忽略。
- **演示策略**：预置 Demo 数据中放 2 条 `lastVisitedAt` 为 300 天前的记忆，与常看记忆形成明暗对比——**评委一眼看懂机制**。
- **阈值可配置**（`fadeStartDays`/`fadeFloor`），避免"38 天开发期看不出来"的问题：Demo 数据直接给旧日期。

### 3.2 回忆重演（Replay Moment）—— 从"查看内容"升级为"回到那一刻"

V1 的"走近时卡片渐变成分层小场景"保留，但固化为**可编排的四拍时序**（总时长 ≈6s，可跳过）：

| 拍 | 时长 | 表现 |
|---|---|---|
| ① 现实退后 | 0.5s | 透视/全景整体压暗到 30%，尘埃粒子升起，环境音淡出 |
| ② 回忆绽放 | 1.5s | 光点炸开为分层伪 3D 小场景（前景/中景/背景依次展开），琥珀色调淡入 |
| ③ 重返当时 | 2.5s | 空间音频（录音/旁白）从场景深处响起，日记文字逐行浮现 |
| ④ 温柔收回 | 1.5s | 场景收拢回光点，现实亮度恢复；**留白 5s 后**星尘路径才点亮下一站（对话之门，借鉴 Rendever） |

- **实现**：`ReplaySequencer`（Coroutine/Playables 时间轴驱动），分层伪 3D、空间音频、字幕全部复用 V1 模块，只新增时序编排层。
- **防眩晕硬规则**：不做相机接管，一切动效发生在用户视野内的光点位姿处；随时可按扳机跳到第④拍。

### 3.3 星河回顾（Constellation Wall）—— 标志性画面

- 走读终点，本房间所有碎片缩略图在弧形墙上排成**星座**：按路线顺序以发光细线相连，私密记忆在本人视角以暗星呈现；点击任意星可立即重演该回忆。
- **实现**：`LineRenderer` 连线 + 缩略图 Billboard + 复用 ReplaySequencer；是演示视频的收尾镜头与截图传播点。

## 4. 视觉规范（V1 空白项，新增）

### 4.1 总基调：暮色暖光

- **色彩**：主色琥珀 #E8A24B（记忆/温暖），辅色青蓝 #5AC8E0（界面/指引），背景暮色 #2B2436；私密记忆光点用暖红 #C86B6B 低饱和。
- **全景选型**：黄昏室内为主（老房间/客厅/书房），自带怀旧氛围，且暖调大图对压缩更不敏感。
- **光点语言**：萤火意象——中心亮核 + 柔和辉光 + 缓慢呼吸（sin 驱动 emissive，周期 3s）；不同记忆类型只换色相不换形制，保持克制统一。

### 4.2 Unity 实现清单（URP）

| 项 | 方案 | 预算 |
|---|---|---|
| 辉光 | URP Bloom（threshold 0.9，intensity 0.6） | 全屏一次 |
| 尘埃粒子 | 单个 GPU 粒子系统，跟随相机 2m 半径，密度 200 | 1 draw call |
| 星尘路径 | 粒子带 + 地面淡光圈（路线下一站高亮） | 2 draw call |
| 转场 | 全屏暗幕（UI Image alpha 曲线），杜绝硬切 | — |
| UI | 磨砂玻璃卡片：半透明深色底 + 1px 描边 + 大字号 TMP 中文字体 | — |
| 色调映射 | 回忆重演期间叠加琥珀色 Color Grading（全局 Volume 切换） | — |

### 4.3 性能预算（4GB 显存 / 一体机 72Hz）

- 全景图：4096×2048 压到 2048×1024，ASTC 6×6，单张 <3MB；同屏只驻留 1 张。
- 碎片贴图：长边 1024，ASTC；碎片按房间分批加载（V1 方案保留）。
- 关闭实时阴影；粒子总量 <1000；目标帧率 Editor 60 / Emulator 72 稳定。

## 5. 交互规范（V1 空白项，新增）

### 5.1 交互原则

1. **全手柄射线为主线**（模拟器可调试、录屏稳定、评委上手零学习）；裸手手势仅 P1 菜单辅助。
2. **先闻其声**：进入光点 3m 半径，其空间音频以 20% 音量隐约响起并随距离增强——用户被声音自然引向记忆，而非被 HUD 指挥。
3. **悬停即预览**：射线悬停 0.3s 浮出小卡片（缩略图/标题/日期），不需要每次点开才知道是什么。
4. **两级确认**：悬停预览 → 扳机点开重演；菜单键随时呼出关闭。

### 5.2 编辑（编排模式）交互

- 抓取光点（握把键）移动/旋转；A/B 键顺序前移/后移；双击扳机在"图片/录音/日记"间切换绑定素材。
- 所有编辑操作即时落盘（脏标记 + 2s 防抖写 `appdata.json`），不存在"保存"心智。

### 5.3 移动与防眩晕清单（逐项验收）

- [ ] 走读模式仅定点传送（传送时 0.3s 暗幕过渡）
- [ ] 记忆面板固定于触发时视线前方 1.5m，不随头转
- [ ] 全景切换/回忆重演全部走淡入淡出，零硬切
- [ ] 用户身高（IPD/站立高度）来自 XR 系统，不做相机动画
- [ ] 音频随传送即时重定位，无"声音残留"

## 6. 架构修订（相对 V1 的 Delta）

V1 §3 架构分层、§4 目录结构、§6 脚本骨架**全部保留有效**，以下为修订项：

| # | 修订 | 说明 |
|---|---|---|
| 1 | **JsonUtility → Newtonsoft.Json**（`com.unity.nuget.newtonsoft-json`） | `diary`/`mediaItems`/`layers` 为 null 时 JsonUtility 反序列化行为不可控（V1 BUG-004 同源）；Newtonsoft 对 null/缺字段容错好，且支持 Dictionary |
| 2 | Schema 升级 v2（见 §7） | 新增 `lastVisitedAt`、`room.theme`、`exportManifest`；`type` 枚举不变 |
| 3 | 新增 `FadeController.cs`（`Scripts/Core/`） | §3.1 褪色机制驱动 |
| 4 | 新增 `ReplaySequencer.cs`（`Scripts/Media/`） | §3.2 四拍时序编排 |
| 5 | 新增 `ConstellationWall.cs`（`Scripts/Core/`） | §3.3 星河回顾 |
| 6 | `ImportServer` 冒烟测试提前到 **W2 第 1 天** | HttpListener 在 Android/IL2CPP 上有兼容风险，第一时间在 Emulator 里跑通"手机→头显"链路；失败降级预案：TcpListener 手写极简 HTTP（只收 POST 文件流） |
| 7 | Android Manifest 需加 `INTERNET` 权限与 cleartext 许可 | PICO SDK 打包模板中确认 |

数据流、模式控制器（编排/走读/个人库/家庭库）、隐私过滤规则不变（V1 §3.3、§5.15）。

## 9. 风险与预案（V1 基础上补充）

| 风险 | 触发 | 预案 |
|---|---|---|
| HttpListener 在 Android 不可用 | W2 冒烟失败 | 降级 TcpListener 手写 HTTP；再不行预置素材 + PC 端演示上传 |
| 褪色在演示中不明显 | 日期都是新的 | Demo 数据预置 300 天前 `lastVisitedAt` 对照样例 |
| Emulator（preview 版）不稳 | 崩溃/透视异常 | 主线 Editor Play；Emulator 只做每周验证，不依赖 |
| D 盘空间不足（已 32GB） | 构建失败 | 开工前清理；Library/构建目录监控，超 20GB 告警 |
| 16GB 内存开发卡顿 | Editor+模拟器+浏览器齐开 | 每周录屏时再全开；日常关模拟器 |
| 分层伪 3D 素材抠图质量差 | 视差穿帮 | V1 预案保留：退化照片卡 + 微视差；Demo 素材优先选景深分明照片 |
| 排期滑点 | M1/M2 延期 >2 天 | 砍序：房间数 2→1 → 星河回顾简化为弧墙 → 褪色保底实现（仅亮度衰减，不做音频滤波） |
| 决赛真机差异 | 入围后锚点漂移/透视色差 | 12-20 后预约线下调试优先改锚点标定；全景模式作无透视兜底 |

V1 §8 的 13 项风险预案继续有效（手势降级、视频降级、导出过滤复核、音量持久化等）。
